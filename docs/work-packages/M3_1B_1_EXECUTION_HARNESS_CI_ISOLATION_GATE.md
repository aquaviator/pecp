# Work Package: M3.1B.1 — Execution Harness & CI Isolation Gate

## Objective

Correct the M3.1B execution harness so normal CI is fast/green, preflight remains the first authority, all execution bindings remain source-driven, and the first real 22-minute k6 run can be performed reproducibly in a dedicated execution path.

Read:

- `docs/PRODUCT_CONSTITUTION.md`
- `docs/M3_1A_CLOSURE.md`
- `docs/work-packages/M3_1B_FIRST_GOVERNED_REFERENCE_EXECUTION.md`
- `docs/M3_1B_PM_REVIEW.md`

Do not assign a PECP performance verdict.
Do not begin M3.2, M3.3 or M4.

## 1. Restore normal CI immediately

The normal repository CI must not require k6 to be preinstalled and must not execute real load tests.

Refactor `ReferenceExecutionHarnessM3_1B.test.ts` so `npm test` verifies orchestration with a controlled injected execution/process adapter rather than invoking the host `k6` binary.

Fast tests must cover:

- preflight blocks before process launch;
- engine-version rejection logic;
- generated command/arguments;
- bundle materialisation equality;
- credential redaction;
- raw-evidence requirements;
- manifest bindings;
- no PECP verdict translation.

Do not mark M3.1B complete from injected/fake runner tests.

A real-k6 integration test may be separate and opt-in, but must not run in ordinary `npm test`.

## 2. Preflight must be first

Reorder `executeReferenceRun()`:

1. bind/validate target and supplied evidence;
2. validate preflight;
3. if blocked, return `PREFLIGHT_BLOCKED` without checking/spawning k6;
4. only then verify pinned engine availability/version;
5. only then materialise/execute.

Add a test proving an invalid preflight causes **zero engine/process calls**, even if k6 is unavailable.

## 3. Remove runner engineering fallbacks

The execution harness is an executor, not another source of RetailCo truth.

Remove project-specific fallbacks for:

- target URL;
- contract version/status;
- runtime version/source id;
- scheduler population/rate/unit;
- business attainment metric/target/unit;
- credential provider/reference/purpose.

Bind these from the validated preflight manifest, Test Definition and bundle.

If mandatory execution binding is absent or inconsistent, fail before process launch with an explicit operational issue.

Runtime metadata such as generated run id/timestamps may be generated by the runner.

Commit SHA may come from an explicit option or authoritative CI environment. If unavailable, represent it as unavailable rather than inventing a SHA.

## 4. Dedicated real-k6 execution path

Create a dedicated execution workflow/script that installs or invokes an explicit pinned k6 version matching `PINNED_K6_VERSION_EXPECTED`.

Requirements:

- do not use `latest`;
- validate actual `k6 version` before the run;
- preserve workflow/run id;
- run only explicitly/manual dispatch or another narrowly controlled trigger;
- do not add the 22-minute run to normal CI.

The dedicated workflow must execute the actual compiler-generated bundle.

## 5. Credential lifecycle ownership

For the real run, generate one ephemeral checkout token.

The orchestrator must supply the same value to:

- the Reference Lab process/server; and
- k6 environment binding.

Never commit or print it.

Mask it in CI before any command that could echo it.

Fast tests must start the Reference Lab with the generated ephemeral token when they exercise authenticated behaviour.

## 6. Smoke execution separation

A short real-k6 smoke run may be used as a diagnostic gate before the canonical run, but:

- it must be explicitly labelled `SMOKE_DIAGNOSTIC`;
- it does not satisfy M3.1B;
- it must not alter or overwrite canonical execution evidence;
- it must not be presented as the governed 22-minute test.

Do not silently use CLI overrides as a substitute for the canonical schedule.

## 7. Full canonical run remains unchanged

The M3.1B closure run must execute:

- the actual current Test Definition;
- actual current generated bundle;
- actual current Reference Lab;
- full 1320-second schedule;
- scheduler peak 109.375 journey iterations/sec;
- business target retained separately as 8.75 orders/sec.

No duration/rate scaling for closure.

## 8. Execution evidence directory/artifact

The dedicated real-run workflow must preserve:

- execution manifest;
- `summary.json`;
- stdout log;
- stderr log;
- all four generated bundle files;
- per-file checksum metadata;
- before/after Reference Lab metrics;
- metrics delta;
- engine version;
- preflight result;
- repository SHA and workflow/run id.

Prefer an uploaded GitHub Actions artifact so evidence survives the ephemeral runner.

No secret values may be present.

## 9. Operational status rules

Operational status precedence must be deterministic:

1. invalid governance/preflight => `PREFLIGHT_BLOCKED`;
2. target cannot be verified => `TARGET_UNAVAILABLE`;
3. engine unavailable/wrong pinned version or launch failure => `EXECUTION_ENGINE_FAILED`;
4. completed process with mandatory evidence captured => `EXECUTION_COMPLETED`.

k6 non-zero threshold exit must be captured faithfully. Do not translate it to PECP PASS/FAIL here.

## 10. CI / tests

After refactor, normal CI must pass:

- `npm ci`
- `npm run lint`
- `npm run test`
- `npm run build`

The normal test suite must succeed on a runner with **no k6 binary installed**.

Report:

- Vitest count;
- Reference Lab native count;
- GitHub CI run id/result;
- whether real k6 was invoked in normal CI (must be NO).

## 11. M3.1B real execution

After M3.1B.1 code/CI is green, perform the dedicated real execution required by M3.1B.

Before the 22-minute run:

- start lab with the generated ephemeral credential;
- probe health/readiness;
- compile Test Definition/bundle;
- build and validate live preflight;
- verify pinned k6 version;
- optionally perform separately-labelled smoke diagnostic;
- execute full canonical 1320-second run.

If any step fails, stop and report the operational failure.

## Non-goals

Do not:

- build Results Model;
- compute workload attainment verdict;
- assign PASS/FAIL/PASS_WITH_OBSERVATION/INCONCLUSIVE;
- generate findings/evidence package;
- begin M3.2/M3.3/M4.

## Definition of Done

M3.1B.1 is complete when:

1. normal CI does not depend on real k6;
2. normal CI is green;
3. preflight executes before engine check;
4. no RetailCo engineering fallback values remain in the generic runner;
5. fast harness tests use controlled injected execution rather than real k6;
6. dedicated pinned-k6 execution path exists;
7. ephemeral token lifecycle configures lab and k6 consistently;
8. real-run evidence is preserved as an artifact;
9. no PECP verdict is assigned.

M3.1B itself closes only after the separate real 22-minute governed execution succeeds operationally and required raw evidence exists.
